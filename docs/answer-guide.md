# 이벤트 기반 사고 확장 비교 가이드

실습을 마친 뒤에는 `12-answer` 브랜치와 아래 파일을 비교하면 됩니다.

- `OrderCreatedEvent.kt`
- `EventPublisherService.kt`
- `NotificationConsumer.kt`
- `OrderService.kt`
- `NotificationService.kt`
- `EventConfig.kt`

## 비교할 때 볼 포인트

- 이벤트가 최소 정보만 담고 있는가
- 발행 서비스가 후속 작업까지 직접 맡지 않는가
- 소비자가 이벤트를 받아 별도 흐름으로 연결하는가
- 주문 생성과 알림 처리가 느슨하게 분리되어 있는가
- 서비스를 분리해서 본다면 어떤 이동 그림이 되는지 설명할 수 있는가

특히 아래 질문으로 비교하면 흐름이 더 잘 보입니다.

- 직접 호출이었다면 어느 서비스가 더 비대해졌을까
- 지금 구조에서는 어떤 책임이 브로커 뒤로 밀려났을까
- 이 이벤트는 사실 전달용인가, 명령 전달용인가
